## 1. 背景：用户反馈和设计结论

- 0.8 面板的问题：
  - 配色是「浓浓的 ChatGPT 祖传配色」，单调，层级和对比都弱。
  - Meeting 页面又长、对比又弱：**历史交接和执行在一个页面上无限堆叠**，会议发言记录显示得不得当。
  - Office 的工位图案在不同状态之间变化不明显。
  - 好评、要保留的：Chat，以及预设的 `@claude` 等收件人；没有聊天时用小字显示实时状态；抽屉审批。
- 用户的思路：一个会议一个文件夹，一条工作流一个文件夹（类似桌面版的「项目」）。文件夹是「流动资产」，成员、租约、笔记、最近动态是「固定资产」。
- 用户最后确认了一个「音乐播放器式」的布局，由 Claude 按协作桥的真实能力微调过，就是 v2 壳子。微调了这几点，落地时**不能退回去**：
  - 只放协作桥真正有的动作，**没有「暂停」「重跑」「跳过成员」**；
  - 进度条只高亮当前阶段，**不做百分比填充**；时间显示「从这一步开始已经过了多久」；
  - 主题在用户手动选择之前跟随系统；
  - 手机上的文件夹页不放大封面，审批卡不用滚动就能看到；
  - Chat 是一个**整页**，入口在顶栏办公室图标的旁边。

## 3. A：服务端，只加只读接口，不改表结构

- `GET /api/folders?limit=&before=`：文件夹列表，按最近活动时间倒序，支持分页。
  - 每个会议是一个夹，它批准后产生的 run 算在这个夹里，不单独成夹。
  - 直接开始的流水线 run（没有对应会议）单独成一个夹。
  - 每项包含：`{ id: "m3" | "r5", kind: "meeting" | "run", title, status, group: "need" | "run" | "done", updated_at, members, counts: { tasks, done, handoffs, rounds }, needs_you }`。`needs_you` 和 `inbox` 同源。
- `GET /api/folders/:id`：一个夹的完整内容。
  - 会议：议题、参会人、每一轮的发言（当前轮给全文，更早的轮次给每人一句摘要，全文按需取 `?round=`）、纪要路径；
  - run：任务、attempt、交接、和这个夹相关的事件。
  - 交接要分页（每页 20 条，`?handoffs_before=`），待审批的那条不管在哪一页，都要在第一页返回。
- `snapshot()` 已有字段不变，只增量加两个：
  - `folders_head`：最近 8 个夹的摘要，主页和工作区首屏不用再多发一次请求；
  - `now_playing`：给底部「正在进行」栏用的。
    - 内容：所有 live attempt 和欠发言的会议轮次，按优先级排好。优先级：有审批门的、`in_progress` 的、`ready` 的、欠发言的会议。
    - 每项包含：`{ folder, task, stage, agent, attempt_id, stage_index, stage_count, since }`。`since` 取这个 attempt 被取走（或这一轮开始）的时间。
    - 没有就返回空数组。
- SSE 不变。前端收到 change 事件后，只重新拉 `/api/state`，以及当前打开的那个夹。

## 4. B：前端按 v2 壳子实现

### 结构（对照壳子）

- **顶栏**：
  - 品牌和项目路径；
  - 后退 / 前进按钮，在面板内部的浏览记录里前后跳，和浏览器的后退联动；
  - 主页按钮；
  - 搜索框，里面带办公室和聊天两个入口；
  - 「＋ 发起」：沿用现有的发起表单（开会讨论 / 直接开始流水线），做成弹窗；
  - 主题切换；
  - 「你」的头像（目前只是装饰）。
- **左栏「工作区」**：
  - 筛选标签：全部 / 会议 / 工作流 / 成员；
  - 固定在第一项的「待你处理」，带数量；
  - 文件夹列表；
  - 成员列表。
  - 1180px 以下收成只有封面的窄栏，有待办的项在封面角上加一个圆点。
- **主区**有四种页面：
  - **主页**：
    - 快捷入口网格：待你处理、最近的文件夹、办公室；
    - 「等你处理」：最紧急的一项做成大卡片，能直接批准或打回，其余的问题卡排在下面；
    - 「进行中」卡片行；
    - 「成员」卡片行；
    - 「最近完成」卡片行。
  - **文件夹页**：
    - 头部：渐变色背景、封面、类型和编号、标题、成员、统计、阶段条；
    - 操作栏：一个大圆按钮，它是**当前唯一主要的动作**：有待审批时是 ✓ 去审批，执行中是 → 看当前这一步，已完成是「以此开新会议」（预填议题，打开发起弹窗）；旁边是停止 / 取消（要确认）和 ⋯；
    - 分区标签：交接 / 任务 / 讨论 / 纪要。默认打开当前阶段对应的那个；会议还没批准时只有「讨论」和「纪要」；
    - 交接是表格，待审批的那行置顶并展开，带批准、打回和备注框；其余是紧凑行，下面有「更早的交接（N）」；
    - 讨论：当前轮的发言并排显示，没发言的人用虚线框占位；更早的轮次折叠成每人一句摘要；
    - 会议的轮次操作（再互评、请定稿、跳过没发言的人、批准或打回定稿）放在讨论区当前轮的卡片里。
  - **办公室**：工位卡片（每种状态有独立的 SVG 图形和颜色）、会议桌、状态图例。
  - **聊天**：整页。消息流加底部输入框，带收件人快捷选择、回复、回执和送达提示。会议和交接的提示是一行，点击跳到对应的夹。没有消息时用小字显示协作桥的实时状态（保留现有行为）。
- **右栏**（可以关闭，1180px 以下浮在上层）有两种模式：
  - **详情（固定资产）**：当前夹或全局的成员（状态和「发消息」，点击跳到聊天页并预选收件人）、文件租约、共享笔记、最近动态。切换文件夹时不重建，正在输入的东西不能丢。
  - **待你处理**：就是 `inbox`，取代现在的抽屉。分「正在进行 / 等你处理 / 接下来」三组，每一项都能直接操作。
- **底部「正在进行」栏**：
  - 显示 `now_playing` 的第一项：封面、任务、阶段、成员，点击成员名和文件夹名能跳转；
  - 中间的按钮：给当前成员发消息、查看这一步、接下来（打开右栏的「待你处理」）、停止工作流（要确认）；
  - 进度条是阶段分段，已完成的灰色，当前的高亮，**不要百分比**，右边写「已 N 分钟」；
  - 右侧：详情、待你处理（带数量）。
  - 没有进行中的事情时显示「空闲」，以及最近完成的一项。
- **手机**（< 768px）：
  - 底部导航：主页 / 工作区 / 聊天 / 待处理；
  - 「正在进行」栏缩成一行，只留主按钮和一条细进度线；
  - 文件夹页隐藏封面；
  - 右栏变成整页。

### 路由和状态

- 后退和前进按钮用的是面板自己的浏览记录，和浏览器的后退保持一致。
- 草稿保留：

  - 沿用现有的 `data-keep` 机制并加以推广。
- 切换页面只是重新渲染，不能触发任何 POST。

### 视觉

## 5. C：修复问题

1. **「确认超时」误报**（`postman.sweep`）：
   - 现象：任务要到交接时才会确认，运行 #3 里每个任务都要做 15 到 25 分钟，结果被标红 4 次，还弹了通知。
   - 修改：对应的 attempt 还在 `in_progress`，而且收件人在超时窗口内有过任何工具调用或进度汇报，就不算超时。
2. **Codex 刚交接完就被判为叫不醒**（`checkWake`）：
   - 现象：04:59:36 Codex 交完 T1，T2 的审查马上排进了 Codex 的队列。可它这一轮还没结束，41 秒后才取信，被记了一次 `wake_timeout`，也算进了失败次数。
   - 修改：给门铃加一个属性，表示「要等这一轮结束才送达」，codex-queue 为 true。按铃前 60 秒内收件人有过工具调用时，宽限期延长（例如加 90 秒，可以配置）。在延长期内取信算成功。
3. **纪要文件名**（`meetings.ts`）：
   - 改成 `<日期>-m<会议号>-<短标题>.md`。短标题从议题里取到第一个标点为止，最多 24 个字符；去掉全角标点、圆圈数字、引号和括号；结果为空就不要短标题。
   - 已经存在的纪要文件不动。
4. **`ai-bridge start` 在端口被占用时静默退出**（`cli.ts` 和 `daemon.ts`）：
   - 现象：7878 已经被一个守护进程占用时，再运行一次 start，会照常打印「项目 / MCP / 面板」等启动信息，然后不报任何错就回到命令行，看起来像是启动成功了（2026-11-20 实际遇到过）。
   - 修改：监听失败时（`EADDRINUSE`）明确报错，并说明那个端口上已经有协作桥在运行（能访问 `/api/state` 就带上它的项目路径），给出怎么处理，进程以非 0 退出码退出。启动信息要等真正监听成功之后再打印。

每条都要在 smoke 里加回归测试。
