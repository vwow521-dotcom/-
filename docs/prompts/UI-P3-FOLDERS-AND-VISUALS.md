## 3. A：Meeting 改成文件夹结构

### A1. 服务端：只加只读接口，不改表结构

- `GET /api/folders?limit=&before=`：返回文件夹列表，按最近活动时间倒序，支持分页。
  - 每个会议是一个文件夹。会议批准后产生的 run 是它的**一部分**，不单独成夹（`meetings.run_id` 已经有这层关系）。
  - 直接开始的流水线 run（没有对应会议的）单独成一个夹。
  - 每项包含：`{ id: "m3" | "r5", kind: "meeting" | "run", title, status, updated_at, members, counts: { tasks, done, handoffs }, needs_you: number }`。
  - `needs_you` 和 `inbox` 同源：这个夹里有几项等你处理。
- `GET /api/folders/:id`：返回一个夹的完整内容：
  - 会议：议题、参会人、每一轮的发言、纪要路径；
  - run：任务、attempt、交接、和这个夹相关的事件。
  - 交接要分页（例如每页 20 条，`?handoffs_before=`），不能一次全给。
- `snapshot()` 保持不变，旧页面和 smoke 还在用。只在里面增量加一个 `folders_head`：最近 5 个夹的摘要，让首屏不用多一次请求就能画出列表。
- SSE 的 change 事件不变。前端收到后，只重新拉**当前打开的那个夹**，以及列表的第一页。

### A2. 前端：Meeting 视图的三栏结构

```
┌ 文件夹列表 ─────┬ 打开的夹（流动资产）──────────────┬ 固定区（固定资产）┐
│ 进行中           │ 头部：标题、状态、参会人、阶段条  │ 成员和当前活动    │
│  ● 会议 #4 …    │ 分区：讨论 | 任务 | 交接 | 纪要   │ 文件租约          │
│ 等你处理 (2)     │   只展开当前阶段需要的那一块；   │ 共享笔记          │
│ 已完成           │   其余折叠成摘要                  │ 最近动态（5 条）  │
│  ○ 运行 #3 …    │ 底部：当前合法操作（固定可见）    │                   │
└──────────────────┴───────────────────────────────────┴───────────────────┘
```

- **文件夹列表**（左栏）：
  - 分组：进行中 / 等你处理 / 已完成；已完成默认折叠，滚动到底时加载更多。
  - 每项显示标题（截断）、状态徽标、等你处理的数量、最近活动的相对时间。
  - 选中的夹写进 URL：`#/meeting/m3`、`#/meeting/r5`。从 Chat 摘要、抽屉、Office 跳过来时，直接打开对应的夹，并定位到对应条目。
  - 没有指定时，默认打开「进行中」的第一个夹；都没有就打开最近的一个。
- **打开的夹**（中栏）：
  - 用分区标签切换：讨论 / 任务 / 交接 / 纪要。默认打开当前阶段对应的那个：收集发言或互评时是「讨论」，执行中是「任务」，有交接待审批时是「交接」。
  - 讨论：每一轮是一个可以折叠的块。当前轮的发言按成员分栏并排，更早的轮次只显示每人一句摘要（已有的 one-sentence 逻辑）。长文默认折叠到大约 8 行。
  - 交接：倒序，每页 20 条，加「更早的交接」按钮。待审批的置顶并醒目显示。
  - 操作区固定在中栏底部，只显示当前合法的动作；会议和执行各自的操作分开，不混在一起。
- **固定区**（右栏）：成员和当前活动、文件租约、共享笔记、最近 5 条动态。它**不跟着夹切换**，只随全局状态刷新。窄屏时折叠成一个「项目信息」抽屉。
- 手机：先显示文件夹列表，点进去是夹的内容，顶部有返回按钮。固定区放进抽屉。
- 旧的 Meeting 单页结构直接替换掉，`/v1`、`/classic` 不变。

## 4. B：修复会议 #1 / 运行 #3 日志里的问题

1. **「确认超时」误报**（`postman.sweep`）：
   - 现象：任务信要到交接时才会确认，而默认超时只有 10 分钟。运行 #3 里每个任务都要做 15 到 25 分钟，结果 4 次被标红，还弹了通知，可对方一直在干活。
   - 修改：信件对应的 attempt 还在 `in_progress`，而且收件人在超时窗口内有过任何工具调用或进度汇报，就不算超时。只有在窗口内完全没有动静时才标红和通知。其他需要确认的信件规则不变。
2. **Codex 刚交接完就被判为叫不醒**（`checkWake`）：
   - 现象：04:59:36 Codex 提交 T1 的交接，桥马上把 T2 的审查排进了 Codex 队列。可 Codex 这一轮还没结束，队列消息要等这一轮结束才会被处理，41 秒后它才取信，超过了 30 秒宽限期，被记了一次 `wake_timeout`，也被算进了失败次数。
   - 修改：给门铃加一个属性，表示「消息要等这一轮结束才送达」，codex-queue 为 true。按铃前 60 秒内收件人有过工具调用时（说明这一轮可能还没结束），宽限期延长，比如加 90 秒，具体可以配置。在延长期内取信算确认成功；延长期过了还没取信，才算失败。
3. **纪要文件名**（`meetings.ts`）：
   - 现象：现在直接截取议题原文，结果是 `2026-11-20-修复-0.8.0-审查留下的小问题：①版本检测在守护进程运行期间不刷新；②「连续.md`。
   - 修改：改成 `<日期>-m<会议号>-<短标题>.md`。短标题从议题里取到第一个标点为止，最多 24 个字符；去掉全角标点、圆圈数字和各种引号括号；结果为空时就不要短标题。已经存在的纪要文件不动，数据库里记的是旧路径。

每条都要在 smoke 里加回归测试。

## 5. C：视觉重做（摆脱「ChatGPT 默认风」）

- **设计目标**：一眼就能分清三件事：**需要我处理的**、**正在进行的**、**已经结束的**。靠颜色、字重、底色和留白一起表达，不能只靠小字。
- **配色**：
  - 不再用白底加单一墨绿的组合。在 `:root` 里重新定义 token：中性色阶 6 到 8 级、一个主强调色、语义色（需要你 / 进行中 / 成功 / 警告 / 危险），以及每个成员一个身份色（claude、codex，以后还会有更多），所有颜色都从 token 取。
  - 主强调色不要用 OpenAI / ChatGPT 的品牌绿，也不要模仿 Claude 或 Discord 的品牌配色。
  - 文字对比度达到 WCAG AA。
  - 同时提供深色模式：`prefers-color-scheme` 跟随系统，顶栏可以手动切换，手动选择存在 localStorage 里。
- **层级**：
  - 页面标题、夹标题、分区标题、条目标题四级要明显不同。
  - 卡片之间用底色区分，少用细线。
  - 状态徽标要做成实心、有颜色的样式，现在那种淡灰描边不够醒目。
- **密度**：文件夹列表和交接列表用紧凑行，展开后再显示详情。
- **Office**：
  - 每种状态有独立的图形，例如工位、电脑、文件、会议桌、警示牌、问号，用内联 SVG 绘制，并配上该状态的颜色。不看小字也能分辨。
  - 成员身份色体现在工位上。
  - 仍然不做「假装在工作」的动效：`unknown` 和 `stale` 只显示静态的问号或灰色。
- **Chat**：布局保留，只换成新的 token；预设收件人和空状态时的小字都保留。
- 不引入 CSS 框架，不加构建步骤；字体用系统字体栈。
